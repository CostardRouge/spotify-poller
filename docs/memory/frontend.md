# Frontend — pages, components, styling

Read before touching a page under `app/(dashboard)/`, a component, `app/globals.css`, the theme, or the keyboard surface.

## `PRODUCT.md` is the review standard, not a mood board (2026-08-20)

Read it before any UI work. It fixes the tone (**instrument, honest, quiet**), the named anti-references (Grafana cosplay, Spotify brand cosplay, AI-SaaS card grids, and the old monospace terminal dump where everything had equal weight), the five design principles, and a WCAG 2.2 AA floor. **How to apply**: the maintainer reviews against it. Two principles bite most often — *freshness before features* (collection health is never more than one glance away, on any viewport) and *phone-complete* (every operator action reachable at 360 px; tables reflow into records, never horizontal scroll).

## Témoin: the paper, the ink, the pen (2026-11-27)

**Decision** (the owner, from the design lab `https://claude.ai/artifact/Uf4Z8zWFjtVXr4UcwefhKE`: name and desktop layout of the "Témoin" direction, paper and trace of "Sismo"; direction A's phone screens were rejected as cluttered, "Greffe" not kept): the product is called **Témoin** and `app/globals.css` carries a new palette — paper `--bg #f2eee4`, sheet `--surface #fbf9f4`, ink `--ink #141613` as the only accent (primary buttons, selected nav), the blue **pen** `--pen #2340a8` for what was recorded, green only for healthy, amber dashed for a declared gap; a "carbon paper" dark theme. It replaces the OKLCH palette carried over verbatim from the pre-Next.js UI (2026-08-20); the variable **names** are unchanged, so every page restyled without being edited. Type: Inter (reading), Inter Tight (`--display`: the verdict and titles), IBM Plex Mono (`--mono`: everything measured), self-hosted from `@fontsource*` packages imported in `app/layout.tsx` — no font CDN at runtime, no network needed by `next build`. **How to apply**: style through the tokens; small status text uses `--ok-text` / `--warn-text` / `--danger-text` (the base `--ok`/`--warn` are fills, ≈3:1 on the paper, AA only for non-text); `--ink-3` is ≥4.5:1 in light but stays ≥18px-or-non-text in dark. Sismo is **not** the product's name: the owner keeps it free for another family of projects.

**The voyant** (`.voyant` in `globals.css`): the status light has a shape per tone — round healthy, square behind, triangle stale/broken — always beside its word. **The trace** (`lib/trace.ts` pure, `lib/server/trace.ts` queries, `components/TraceStrip.tsx` SVG): one strip per LOCAL day, 96 proportional slots (a 23/25-hour DST day stretches), each slot a needle swing growing with plays, the pen lifted over declared gaps (dashed amber, returned as their own path), today cut at "now" with a pen mark and nothing drawn after it. Server-rendered, no chart library. **The Overview** reads in one order on every viewport: voyant + one sentence (`lib/verdict.ts`, shared with the top bar, which hides its own chip on `/`), the actions, then evidence — today's strip and the collectors row on a phone; the dial of today's polls (drawn where each poll happened, from `poller_runs`, not an ideal schedule) and the week on a desk — then recent runs and the latest gap (the Stored data / Server panels left on 2026-11-27: counts → Journal, server → System). **`/trace`** shows a week per page (`?week=N`), jump key **9** (appended). Phone tabs: since 2026-11-27 Now, Trace, Library, Journal (see "Navigation: five places"). Server components read the clock through `renderTime()` (`lib/clock.ts`): React's purity rule rejects a bare `Date.now()` in a component body.

## No state carried by colour alone (2026-08-20)

Every status dot is paired with a word (`PRODUCT.md`, `components/StatusPill.tsx`, the sidebar health chip). A new indicator that is only a coloured dot will be rejected.

## The keyboard surface is part of the product (2026-08-20)

⌘K command palette, `1`…`7` to jump to a section, `/` focuses the events search, `T` cycles the theme, `R` refreshes, `?` lists shortcuts, `Esc` closes every overlay. Native `<dialog>` is used for overlays (the event payload inspector, the account menu, shortcuts) — "earned familiarity": standard affordances only, nothing invented for flavour. **How to apply**: adding a section means adding it to the palette and to the numbered jumps, or the surface silently becomes inconsistent.

## The theme read is deliberately deferred past first render (2026-08-20)

`eslint.config.mjs` downgrades `react-hooks/set-state-in-effect` to `warn` for exactly one reason: `ThemeToggle`'s one-time `localStorage` read in a `useEffect`. Reading `localStorage` during render would crash server-side and desync client/server HTML, so the deferred read is the correct pattern — the rule (eslint-plugin-react-hooks v7, pulled in by eslint-config-next 16) has no case for it yet. **How to apply**: do not "fix" the warning by moving the read into render, and do not silence the rule repo-wide beyond this.

## The icon set and the web manifest (2026-10-19)

**Decision** (the portfolio standard, C11): the dashboard ships the whole set under `public/icons/` — three SVG sources (`icon.svg` the rounded tile, `icon-apple.svg` and `icon-maskable.svg` full-bleed) and the PNGs `scripts/gen-icons.mjs` rasterises from them with `sharp`, which is already in `node_modules` as an optional dependency of Next (never a dependency of this project; `npm i --no-save sharp` if it ever goes). `app/layout.tsx` declares them through `metadata.icons`, `metadata.manifest` and `appleWebApp.title`; `public/manifest.webmanifest` is a static file with **relative** paths, `display: standalone` because the state lives on the server (a standalone home-screen launch loses nothing, unlike Atelier's browser-held projects), and `theme_color` / `background_color` set to the light `--bg` as hex, `#f2eee4` since Témoin — the same value `viewport.themeColor` declares, so the two move together with `app/globals.css`. **Why**: iOS builds a home-screen icon from `apple-touch-icon` alone, a PNG, square and opaque (a transparent corner is composited onto black), and ignores `rel="icon"` whatever its type; the SVG favicon that was the whole set until now gave a phone a screenshot of the login page. **Name and drawing** (2026-11-27): `name`, `short_name` and the iOS title are `Témoin` — six letters, so the launcher never cuts it (the old `Poller` was a truncation of `spotify-poller`). The mark is the ink tile with the trace in paper colour and the blue pen dot, deliberately without green (a static icon cannot know health; the previous tile was Spotify green, a brand cue `PRODUCT.md` rules out); `components/Mark.tsx` draws the same thing inline for the sidebar and sign-in. **And** the auth gate leaves `/icons/*` and `/manifest.webmanifest` out of its matcher, with the other session-less static files (`auth.md`). **How to apply**: edit a source, run the generator, commit the PNGs with it; `tests/icons.test.ts` holds the sizes, the touch icon's missing alpha and the manifest's paths, so a forgotten regeneration fails the gate. The showcase on GitHub Pages reuses the same files (`pages.yml` copies `public/icons`), with the SVG sources as its favicon.

## `allowedDevOrigins` is set for a reason (2026-08-20)

`next.config.mjs` lists `localhost` and `127.0.0.1` (`5c46819`). Next 16 blocks cross-origin dev requests otherwise, which breaks the dev container reached from the host.

## Navigation: five places, one account menu (2026-11-27, design lab iteration 2)

**Decision** (the owner's "go" on the iteration-2 canvas, `temoin-design-canvas` in team memory): ten sidebar entries became five places in three groups — Watch: Now, Trace, Journal; History: Library; Instrument: System — declared once in `lib/nav.ts` (`SECTIONS`, `GROUPS`, `SUBVIEWS`, `sectionOf`). Library's views are Plays `/events`, Sessions `/playback`, Trends `/listening`; System's are Server `/system`, Accounts `/accounts`, Storage `/database`, drawn as the `.subnav` pills under the title (`Topbar.tsx`, `?account=` kept). **Journal** (`/journal`) merges Runs, Gaps and Stats: `lib/journal.ts` (pure, tested) interleaves one page of runs with the gaps started inside that page's window (`journalRuns`/`gapsBetween` in `db.ts`, window = [oldest run of the page, oldest run of the page before)), a gap placed at `from_utc`, days cut on the local clock; `/runs` `/gaps` `/stats` are `redirect()` stubs keeping `?account=`. **No desk top bar**: the voyant + "polled X ago" sits under the mark, ⌘K is a "Jump to…" field, the account button closes the sidebar. **One account menu** (`components/AccountMenu.tsx`, one `<dialog>` opened by `sp:open-account`, anchored above the sidebar button on a desk, a bottom sheet on a phone) replaced the settings dialog, the Viewing select, the sidebar theme switch and the phone's More sheet: viewing (radio, `?account=` only), theme, export, backup, shortcuts (desk only), System with its "N to check", version, sign out. **Each fact has one home**: the server rows are `lib/server/system.ts` (`systemChecks`), drawn on System only and counted (`warn`) for the sidebar/menu badge; run buttons live on Now (artists: the Listening genres empty state and ⌘K). **Phone**: four tabs Now/Trace/Library/Journal (gap badge on Journal) + the header's round account button; nothing is desk-only. One `/api/status` poll for the whole shell (`components/useStatus.ts`), carrying a client-side `fetched_at` that renders use as "now" (react-hooks/purity rejects `Date.now()` in render). **Rejected**: keeping a top bar with chip/search/gear (each had a twin), a "More" tab (a junk drawer), Runs/Gaps/Stats as Journal tabs (they are one story). **Trap**: an element cannot container-query itself — `@container` and `@4xl:grid-cols-*` on the same node read the next container up; wrap the grid. **How to apply**: a new page goes into a section's `routes` (and `SUBVIEWS` if it is a view), `Topbar`'s `TITLES`, the palette `SECTIONS`; a preference or one-off maintenance gesture goes in the account menu, configuration on System.

## The Listening page: every chart is a link, and no client JavaScript (2026-08-21)

**Decision**: `/listening` renders server-side and cross-filters through the **query string** — every bar, heatmap cell, calendar square and ranked row is an `<a>` whose href is "the current filter, with one thing changed" (`link()` in `app/(dashboard)/listening/page.tsx`), and the only form is a plain `method="get"`. **Why**: the interesting questions are intersections ("Sunday nights", "techno in the morning"), and a link-based filter gives them for free — bookmarkable, reload-proof, back-button-correct, no hydration, no chart library. **How to apply**: a new facet is a field on `ListeningFilter`, a branch in `filterToParams`, a chip in the page's `facets` list and a hidden input in the form (otherwise clicking Apply silently drops it). A 2-D control toggles as a **pair**: toggling each axis separately makes clicking a Sunday cell *unpin* Sunday when Sunday is already selected.

## Volume is drawn in neutral ink, never in the accent (2026-08-21)

**Decision**: bars, heatmap cells and calendar squares scale `color-mix(in oklab, var(--ink) N%, var(--surface-2))`; the accent marks only what is **selected**, and a selected item is additionally underlined. **Why**: `PRODUCT.md` reserves green for *healthy*, so a green heat ramp would be asserting something false about a busy Tuesday, and a Grafana-style ramp is a named anti-reference. The underline is what keeps the selection from being carried by colour alone. **How to apply**: same rule for any future density view.

## Zero-based axes, with the numbers printed under short ones (2026-08-21)

Weekday and month bars sit within a few percent of each other, so the shape says nothing. The fix is `showValues` on `BarChart` (the count under each tick), **not** a cropped axis — truncating the baseline to dramatise a 5% difference is exactly the dishonesty `PRODUCT.md` rules out.

## Section shortcuts are appended, never renumbered (2026-08-21)

`/listening` became jump key **8** rather than taking a lower number matching the sidebar order. The 1…7 mapping predates the Next.js UI and is muscle memory; the sidebar and the jump list have never matched, and reordering costs more than the consistency is worth (`components/CommandPalette.tsx`). Adding a section still means: `lib/nav.ts`, palette `SECTIONS`, the jump map, `ShortcutsDialog` and `Topbar`'s `TITLES`. Since 2026-11-27 each key lands where its old page's content went (3 Runs, 4 Gaps, 5 Stats → Journal) and `0` is System.

## Phone layout: what made it overflow, and the reflow contract (2026-11-26)

**Trap**: a `.panel` is a grid/flex item almost everywhere, and such an item never shrinks below its content's min-content width — a nowrap timestamp column three levels down made every Overview panel ~80 px wider than a 390 px screen, and `main`'s `overflow-x: hidden` silently cut the Run buttons off instead of scrolling. **Remedy**: `.panel { min-width: 0 }` in `app/globals.css`; any new grid/flex child that holds a table or a long unbreakable string needs the same. **Rows**: `.rows` is a size container and a `.row` puts the label above the value below 28rem of *panel* width (the 9rem label column left ~45 px for the value) — 2026-11-27, was a 36rem *viewport* query, which missed half-width panels beside the 240 px sidebar at 768–1280 px windows. **Mid widths are the hard case, not phones** (2026-11-27): the sidebar appears at md and eats 240 px, so a 1024 px window leaves ~720 px of page; layouts that split on `md:` viewport breakpoints squeezed the Now page's status card to a ~30 px collector column. **Remedy**: the Now page root is `@container`; its top pair splits at `@4xl` (56rem of page), the lower pairs at `@3xl`, and the status card is its own container (dial beside the collectors from `@[21rem]`, stacked above otherwise; rows `flex-wrap` so Run now drops under the text). The dashboard root has `overflow-x-clip` so an overflow can never scroll the window sideways (Safari did, which shoved the sidebar's "Viewing" against the left edge); `clip`, not `hidden`, so no scroll container is created. **How to apply**: split a page's columns with container queries (`@container` + `@3xl:` etc.), not `md:`/`lg:`, whenever the sidebar is beside it. **Tables reflow into records below md** (`PRODUCT.md`'s phone-complete), one CSS contract, no JavaScript: `<table class="records">`, each body cell `data-label="…"` (printed above the value), no label = headline or whole-row cell spanning both columns, `rec-wide` = labelled but full width, `rec-act` = the row's action bottom-right, an empty cell disappears. **How to apply**: a new table gets `records` and a label on every cell, or it scrolls sideways on a phone again; the CSS is unlayered so it beats Tailwind's `px-3`/`truncate` on the same cells. Checked by measuring `scrollWidth` on every page at 390 px (and, since 2026-11-27, at 768/820/954/1024/1180 px against elements overflowing their box) with Playwright — no unit test can see it.

## The installed app: safe areas, 16 px fields, a worker that caches nothing (2026-11-26)

**Safe areas**: `viewport.viewportFit: "cover"` (`app/layout.tsx`) is what makes `env(safe-area-inset-*)` non-zero; `body` takes the side and top insets, the fixed tab bar (`.tabbar`) and `main` (`.tabbar-clearance`) the bottom one. Without it the owner's iPhone app showed the tab bar clipped by the rounded corners and crossed by the home indicator. Status bar stays `default`: `black-translucent` puts white status text over the light theme. **Fields**: on `pointer: coarse` every text input, select and textarea is ≥16 px, because iOS zooms the page into anything smaller and stays zoomed; the desk keeps 13 px. **Service worker** (`public/sw.js`, registered in production only by `components/ServiceWorker.tsx`): intercepts GET navigations only and answers `public/offline.html` when no response comes back at all — it **caches no page, API or asset on purpose**: a cached report shown while the server is down would be a stale "Healthy", exactly the dishonesty `PRODUCT.md` forbids. The offline page says "unreachable", never "down", and names the watchdog as the only judge of silence. **How to apply**: never add a caching strategy to the worker; changing `offline.html` means bumping `VERSION` in `sw.js`; `tests/pwa.test.ts` asserts the worker puts nothing in a cache. Manifest `shortcuts` (Gaps, Runs, Events, Listening, relative URLs) are held to existing pages by the same test.

## Link previews and indexing (2026-11-26)

**Decision**: the dashboard is `noindex` (metadata `robots`) and `public/robots.txt` disallows everything — a private instance is never a search result; the project's public face is the showcase. OpenGraph/Twitter tags exist for links pasted into a chat: the fetcher has no session, lands on `/login`, and reads the card `public/og.png` (1200 × 630, drawn from `scripts/og-card.svg` by `scripts/gen-icons.mjs`) — name and purpose only, never data, and no green dot because a drawing cannot know health. `og:image` must be absolute and the app has no public-URL setting (LAN name, proxy domain and localhost all reach one instance), so the root layout's `generateMetadata` builds `metadataBase` from the request (`lib/server/origin.ts`: forwarded host/proto first, held to hostname characters; `tests/origin.test.ts`). **How to apply**: edit the SVG and re-run the generator, never the PNG; the generator also re-rasterises the favicons, which come out byte-different under another sharp — revert them if their source did not change.
