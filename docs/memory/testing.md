# Verification, CI, the showcase pipeline

Read before relying on "the tests", touching a workflow under `.github/workflows/`, or the showcase.

## The unit tests: Node's runner through tsx, over pure server logic (2026-10-19)

**Decision** (the portfolio standard, E3): `npm test` is `node --import tsx --test "tests/**/*.test.ts"` — no new dependency, since `tsx` is already a runtime dependency for the CLI scripts, and Node's `--test` expands the quoted glob itself. The files cover `intParam` and `buildEventWhere` (the account scope first in clause and parameter lists), `localtime` (an offset at an instant, the DST segments, the SQL they become, the local-to-UTC bounds), the backup's naming and rotation with `DB.backup` stubbed in a temp directory, the Listening filter's round trip through the query string, and invariant I2 — a replay inserts nothing, two accounts never share a row — on an in-memory better-sqlite3 database with `migrations/*.sql` applied in name order. **That last suite replicates the migrator's loop**: `scripts/migrate.ts` opens `DB_PATH` on load and cannot be imported, so `tests/events.test.ts` reads the same files in the same order; a change to how migrations are applied must reach it too. **Traps**: `__dirname` works in a test because tsx runs `.ts` as CommonJS here (no `"type": "module"`), exactly as it does for `scripts/migrate.ts`; a run that dies with `Assertion failed: (env) != nullptr` is the Node, not a test (better-sqlite3 on 24.19 and later, `deployment.md`), which is why `ci.yml` reads the exact pin; the tests are type-checked by `tsc` and by `next build` alike (`tsconfig.json` includes `**/*.ts`) and linted with the rest, so a sloppy test fails the gate like sloppy code. **What verification means here now**: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, plus — for collector or database work — the manual curl round-trips in `README.md`: idempotence (replay `played` twice, second run inserts 0), the backup/export/import round-trip (`grep -c refresh` on the NDJSON must return 0), and account isolation after connecting a second account. **How to apply**: a bug fix in `lib/server` ships with a test that fails without it; nothing under `tests/` may reach the network, a Spotify account or a file outside a temp directory, and never `./data`; "tested" still means those round-trips for anything the unit tests cannot see (the collectors' HTTP paths, the scheduler, the auth gate, the pages).

## `next lint` no longer exists (2026-08-20)

Next 16 removed it, so ESLint is invoked directly (`npm run lint` → `eslint .`) with a flat config that spreads `eslint-config-next` (`eslint.config.mjs`). The `ignores` block there also covers `site/` and `showcase/`, which are output and hand-written static HTML respectively.

## The pull request gate (2026-10-19)

**Decision** (the portfolio standard, C15): `.github/workflows/ci.yml` runs the gate — `npm ci`, `npm run lint`, `npm run typecheck`, `npm run build` — on every pull request and every push to `main`, on the Node of `.nvmrc` (the exact 24.18.0; `deployment.md` says why a floating major would make this very job flaky) and on a named `ubuntu-24.04`. Until then only bookkeeping ran on a pull request — `registry.yml`'s `check` (the Registry block) and `release.yml`'s `check` (`CHANGELOG.md` against `package.json`'s version) — and a lint or type error reached `main`, caught only when `docker-build.yml` failed at `npm run build`, after the merge. **What the gate still does not cover**: the Docker image itself (the native better-sqlite3 build on Alpine — `docker-build.yml`, after the merge), the showcase pipeline (`pages.yml`, after the merge) and anything that needs a Spotify account. **How to apply**: a command `CLAUDE.md` calls part of the gate is in `ci.yml`, or `CLAUDE.md` stops calling it that. `next build` needs no environment variable — it passes with none: only `/login` is prerendered and it opens no database — so the job sets none; a change that makes the build read `.env` would turn the gate red and is the signal to look at, not to paper over with throwaway values like `pages.yml`'s.

## The showcase runs the real app against fixture data (2026-08-20)

**Decision**: `pages.yml` builds the app, migrates, seeds `scripts/seed-demo.ts`, starts the server, drives it with Playwright (`scripts/showcase-screenshots.mjs`) and publishes real screenshots to GitHub Pages. **Why**: the screenshots are of the actual UI, so they cannot drift from it — and no real Spotify credentials are involved (the workflow sets throwaway `SPOTIFY_CLIENT_ID=demo`, `ADMIN_TOKEN=showcase-demo-token`, etc. as plain env, which is safe precisely because they unlock nothing). One-time repo setup: Settings → Pages → Source "GitHub Actions".

**The trap** (`1fc6f95`): the screenshot script waits on **UI copy** — `page.waitForSelector("text=Run now")`, `getByLabel("Admin token")`, `getByRole("button", { name: "Payload" })`. Renaming a button or a label silently breaks the Pages deploy, and the failure appears in a workflow nobody was looking at. **How to apply**: when you rename visible control text, grep `scripts/showcase-screenshots.mjs` for the old string in the same change.

The script is runnable locally against a seeded instance (invocation in its header comment), and honours `CHROMIUM_PATH` so an environment with a pre-installed browser can skip `playwright install`.

**The page is a public page and is treated as one** (2026-10-19, the portfolio standard's C17): `showcase/index.html` carries a meta description, a canonical address (`https://costardrouge.github.io/spotify-poller/`), OpenGraph and Twitter tags whose image is the dashboard screenshot the workflow captures (2880 × 1800 — a 1440 × 900 viewport at 2×, not the 1200 × 630 card the standard prefers; a card drawn on purpose is the next step if link previews ever matter), the app's icon set copied from `public/icons`, and a legal notice whose facts are copied from Versus's and Tamalou's notices: publisher Steeve Pommier, a private individual; host GitHub Pages (GitHub, Inc.'s address); no measurement at all — the page loads no tracker and no third-party resource, which is the fact the notice states and `grep -c "<script" showcase/index.html` keeps true at 0; MIT. **How to apply**: a tracker or a font added to the page changes the notice in the same commit; the OpenGraph image is the dashboard shot, so renaming or dropping that screenshot in `scripts/showcase-screenshots.mjs` breaks the preview silently — grep the HTML for the file name when touching the script.
